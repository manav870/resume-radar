Documentation & Operations

System Architecture & Setup Guide

Everything you need to know about Resume Radar: the 4-stage pipeline, deterministic scoring formula, Google Drive Service Account integration, and REST API specification.

1. End-to-End Processing Pipeline

Core Pipeline

Resume Radar operates as a robust, high-throughput pipeline designed to handle diverse resume formats without human fatigue or bias:

Stage 1: Ingest

Batch fetches resumes from Google Drive or direct multipart upload. Supports PDF, DOCX, DOC, and TXT files seamlessly.

Stage 2: Extract

Gemini AI maps unstructured text into a validated candidate schema with automated fallback models and error recovery.

Stage 3: Score

Transparent mathematical scoring formula evaluates candidates against JD criteria with comprehensive alias mapping.

Stage 4: Decide

Exports Google Docs evaluation dossiers and enables recruiters to shortlist, reject, or schedule interviews in real time.

2. The Deterministic Scoring Engine

100% Auditable

Standard AI screeners output arbitrary, opaque scores that fail compliance and explainability standards. Resume Radar uses a deterministic mathematical formula where every point is auditable:

Final Score = (W_req × S_req) + (W_pref × S_pref) + (W_exp × S_exp) + (W_edu × S_edu) + (W_cert × S_cert)
Required Skills (40% default): Percentage of mandatory skills verified in the candidate's skills list, projects, or work history highlights. Uses bidirectional alias normalization (e.g. k8s ↔ kubernetes, js ↔ javascript).
Preferred Skills (15% default): Bonus score awarded for secondary, nice-to-have capabilities requested in the role.
Experience Match (25% default): Ratio of total verified years of domain experience compared to the job requirement (capped at 100%).
Education Match (10% default): Degree hierarchy comparison (High School = 1, Associate = 2, Bachelor's = 3, Master's = 4, PhD = 5).
Certifications & Credentials (10% default): Matches required industry credentials or verified portfolio project evidence.

3. Google Drive Service Account Configuration

Cloud Integration

Follow these 4 simple steps to connect your Google Drive resume folder:

1
Enable Google Drive & Docs APIs
In the Google Cloud Console, navigate to APIs & Services and enable both the Google Drive API and Google Docs API.
2
Generate Service Account Key
Create a Service Account, generate a JSON Key, and save it as backend/service-account.json (or point the GOOGLE_APPLICATION_CREDENTIALS environment variable to it).
3
Share Your Drive Folder with the Service Account
Open your Google Drive resume folder, click Share, and paste your Service Account's email address (e.g., your-app@project-id.iam.gserviceaccount.com) with Viewer or Editor permissions.
4
Copy the Folder ID
The Folder ID is the string of characters at the end of your browser URL:
https://drive.google.com/drive/folders/1a2B3c4D5e6F7g8H9i0jK

4. REST API Specification

Developers
POST /api (or /process-batch)
Batch screens resumes from Google Drive. Body: { inputFolderId, outputFolderId, maxFiles, jobCriteria, customWeights, generateDocs }
POST /api/jobs/parse
Extracts structured requirements from raw text or uploaded JD file (PDF/DOCX via multipart/form-data).
POST /api/candidates/screen-file
Directly evaluates a single uploaded resume file against job criteria.
POST /api/candidates/review-status
Updates human-in-the-loop candidate review status (shortlisted, rejected, interview_scheduled, hold).
GET /api/status & /health
Returns real-time service health, Gemini API key status, and Google Cloud credentials status.
